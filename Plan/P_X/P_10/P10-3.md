**典型 Insert 骨架（悲观版）**

```cpp
bool BPlusTree::Insert(const KeyType &key, const ValueType &value) {
  Context ctx;
  ctx.root_page_id_ = GetRootPageId();
  WritePageGuard header_guard = bpm_->FetchPageWrite(header_page_id_);
  // X latch header 取 root

  WritePageGuard guard = bpm_->FetchPageWrite(ctx.root_page_id_);
  ctx.write_set_.push_back(std::move(guard));

  while (!ctx.write_set_.back().As<BPlusTreePage>()->IsLeaf()) {
    auto *internal = ctx.write_set_.back().AsMut<InternalPage>();
    page_id_t child_id = internal->Lookup(key, comparator_);
    WritePageGuard child_guard = bpm_->FetchPageWrite(child_id);
    // 若 child safe，可 pop 释放祖先；悲观版不释放
    ctx.write_set_.push_back(std::move(child_guard));
  }

  auto *leaf = ctx.write_set_.back().AsMut<LeafPage>();
  if (leaf->Insert(key, value, comparator_)) return true;
  // split + 向上传播，write_set_ 提供父 latch
  return SplitAndInsert(key, value, ctx);
}
```

- 你要对照自己项目代码：safe 判定、Release 时机可能略有不同。

**PageGuard 生命周期陷阱**

**陷阱 1：Guard 移动后仍使用旧指针**
```cpp
WritePageGuard g = FetchPageWrite(id);
auto *p = g.AsMut<LeafPage>();
WritePageGuard g2 = std::move(g);  // g 失效
p->Insert(...);  // UB
```

**陷阱 2：write_set_ 存 guard，但 split 时又 Fetch 同一 page**
- 同一 page 双 X latch -> 自死锁（若 latch 不可重入）。

**陷阱 3：析构顺序**
- 先获取 A 再 B，释放应先 B 后 A；deque 尾部是叶，pop 从祖先开始。

**陷阱 4：忘记 latch header page**
- root_page_id 在 header，改 root 时与 Insert 竞态。

**边界测试清单**

**单线程回归（先过 P8）**
- Insert/Delete/Iterator 全过再开并发。

**两线程并发**
- T1/T2 同时 Insert 不同 key（不同子树）——应无 deadlock。
- T1/T2 同时 Insert 同一满叶——不应 corrupt，最终 key 都在。
- T1 Insert，T2 GetValue 同一 key——不应 torn read。

**压力测试**
- N 线程随机 Insert unique key，M 秒后全树 Iterator 有序且 size 正确。

**死锁检测**
- 运行带 timeout 的测试；若 hang，用 TracedLatch 日志看最后等的 page_id。

```cpp
// 伪：带 timeout 的线程 join
std::thread t1([&]{ tree.Insert(...); });
std::thread t2([&]{ tree.Insert(...); });
if (!join_with_timeout(t1, t2, 5s)) {
  FAIL() << "possible deadlock";
}
```

**区分 latch bug vs 结构 bug**

```text
现象                          更可能原因
------------------------------------------------------
随机 segfault                 使用 moved guard 指针
hang 不结束                   死锁 / 自锁同一 page
部分 key 丢失                 P8 split 逻辑（也检查 latch）
Iterator 乱序                 P8 next 链（非 latch）
Stress 通过单测 fail          race，缩小到 2 线程
```

- 调试策略：
- 单线程关掉并发测试 -> 仍 fail = P8
- 单线程过，两线程 fail = P10

**ReadPageGuard 读路径示例**

```cpp
bool BPlusTree::GetValue(const KeyType &key, std::vector<ValueType> *out) {
  ReadPageGuard guard = bpm_->FetchPageRead(GetRootPageId());
  while (!guard.As<BPlusTreePage>()->IsLeaf()) {
    auto *internal = guard.As<InternalPage>();
    page_id_t child = internal->Lookup(key, comparator_);
    ReadPageGuard child_guard = bpm_->FetchPageRead(child);
    guard = std::move(child_guard);  // 释放父
  }
  auto *leaf = guard.As<LeafPage>();
  ValueType v;
  if (leaf->Lookup(key, &v, comparator_)) {
    out->push_back(v);
    return true;
  }
  return false;
}
```

**与事务 Lock 的共存（概念）**
- bustub 基础并发 B+Tree 项目通常 **只测 latch**，不涉及 2PL。
- 完整系统：
- 事务 lock 决定能否读 tuple
- latch 决定 B+Tree page 能否改

- 不要在一个函数里混：
```cpp
lock_manager->LockRow(...);
// ... 长事务 ...
page_guard = FetchPageWrite(...);  // latch 应极短
```

**Hash Table 并发（P7 扩展）**

- split 时：先 latch directory，再 latch 两 bucket
- 顺序：directory 先于 bucket，避免看到半 split 目录

**并发测试用例模板（可直接抄进 gtest）**

```cpp
TEST(ConcurrentBPlusTree, TwoThreadsInsertSplit) {
  BPlusTree tree(...);
  std::barrier ready(2);
  auto worker = [&](int base) {
    ready.arrive_and_wait();
    for (int i = base; i < base + 500; i++)
      ASSERT_TRUE(tree.Insert(i, Rid{i}));
  };
  std::thread t1(worker, 0), t2(worker, 500000);
  t1.join(); t2.join();
  for (int i = 0; i < 1000; i++) { /* 只查本测试插入的 key 子集 */ }
  CheckLeafChain(tree);
}
```

- 要点：两线程 key 空间错开便于定位；join 后 quiesce 再 CheckLeafChain。
- 加 `ASSERT_TRUE(join_with_timeout(t1, 5s))` 防死锁 hang。
