这一段我们深讲 `P10` 的核心算法：**latch crabbing**（亦称 crabbing/coupling），以及 Insert/Delete/Lookup 在并发 B+Tree 上怎样获取和释放 S/X latch，怎样避免死锁。**P10-2 开始**

**今天这次的目标**
- 搞懂 crabbing 的“安全节点”条件。
- 能描述 Insert 写路径何时释放父 latch。
- 能构造一个最小死锁场景并给出避免规则。

---

**Latch Crabbing 是什么**
- 是什么：
- `从根向叶加 latch，向下“爬”时，若子节点 safe 则释放祖先 latch，避免长时间锁整路径。`

- 为什么叫 crabbing：
- 像螃蟹横向移动——锁抓在当前和下一层，旧层放开。

- 没有 crabbing：
- 要么锁整棵树（无并发）
- 要么只锁叶（split 时父节点竞态 corrupt）

---

**Safe Node 定义（Insert 视角）**
- 节点 **safe** 当：
- `Insert 后不会 split` —— 即 `size < max_size`（Insert 前 `size <= max_size - 1`）。

- 节点 **unsafe** 当：
- `Insert 后可能 split` —— 叶/内节点已满 `size == max_size`。

- Delete 视角的 safe（略不同，P10-3 详述）：
- `Delete 后不会 underflow` —— `size > min_size`。

- 为什么 Insert 和 Delete safe 不同：
- 阈值一个是 max，一个是 min。

---

**Insert 的 Crabbing 写路径**

```text
1. X latch root
2. current = root
3. while current 不是 leaf:
     child = 选 child page
     X latch child
     if child is safe for insert:
         unlatch 释放 current（及更早祖先）
     current = child
4. 在 leaf 上 Insert
5. 若 leaf split -> 可能需 X latch 父（若已释放则要重新从根或乐观重试）
6. 释放剩余 latch
```

- **关键点**：
- 若 child unsafe（已满），**不能**释放 current——因为 split 可能要更新 current（父）。

- 小例子：
- 根 R 有 2 children，目标叶 L 满。
- 路径 R -> I -> L，L 满则 I、R 可能都要保留 X latch 直到 split 完成。

---

**Lookup 的 Crabbing 读路径**

```text
1. S latch root
2. while 不是 leaf:
     child = ...
     S latch child
     S unlatch parent   // 读路径几乎总是可以释放父
     current = child
3. S latch leaf 内读 key
4. S unlatch leaf
```

- 为什么读路径总能释放父：
- 读不会 split/merge，父结构不变（在无写并发时）。
- 有写并发时：读可能看到旧版本，但不应 torn write——写线程 X latch 保证。

- 易错点：
- 读 leaf 时释放太早，写线程 split 换页 -> 读 stale page_id——需重新验证或 crabbing 变体（乐观）。

---

**Delete 的 Crabbing 写路径（概要）**
- 与 Insert 类似，但 safe = `size > min_size`。
- 若 child unsafe（删后会 underflow），保留父 X latch 以便 merge/redistribute。

```text
X latch 沿路径下降
child safe for delete -> 释放祖先
leaf 上 Remove
underflow -> merge/redistribute，可能需要兄弟 X latch
```

- 兄弟 latch 顺序：
- 固定 `left_sibling page_id < right_sibling page_id` 加锁，防死锁。

---

**Split 时的 Latch 协调**
- Insert 到满叶 L：
- 路径上祖先可能已 X latched（若 L unsafe）。
- 分配新页 L'，X latch L'。
- 改 L、L' 内容，改 leaf next。
- X latch 父（若还在 write_set 里已有）。
- 父 Insert 分隔 key，父满则递归 split。

- 若 Insert 过程中曾释放父 latch：
- **乐观 crabbing**：split 时重新 latch 父；若父已被别人改，重试。
- bustub 并发 project 常用 **悲观**：unsafe 路径不释放 latch。

- bustub 教学版常见策略：
- **写操作：从根到叶全程保留 write_set 中所有 X latch，直到 split 完成**——简单，并发低，但正确。
- 进阶：只在 unsafe 时保留祖先。

---

**两种 Crabbing 策略对比**

```text
策略              并发度        实现难度      bustub 常见
--------------------------------------------------------
悲观（unsafe 不放手）  低            低            入门通过
标准 crabbing         中            中            进阶
乐观 B-link/版本号      高            高            工业变体
```

- 你先实现悲观版正确，再优化。

**死锁场景构造**

**场景 1：不同顺序锁兄弟**
- Thread A：X latch leaf 10，要 latch leaf 12（兄弟）
- Thread B：X latch leaf 12，要 latch leaf 10
- -> 死锁

- 规则：**总是先 latch page_id 小的兄弟**。

**场景 2：读升级写（若允许）**
- Thread A：S latch 父，等 X latch 子
- Thread B：X latch 子，等 S latch 父
- -> 死锁

- 规则：**B+Tree 一般禁止 latch 升级；直接以 X 模式重新 latch**（释放 S 再 X，或一开始就 X on write path）。

**场景 3：Insert vs Delete 交叉**
- 复杂，靠固定 page_id 全局顺序 + 限制同时 latch 页数。

---

**加锁顺序黄金规则**
- 规则 1：B+Tree 路径从上到下获取 latch。
- 规则 2：需要两页时，**page_id 小者先**。
- 规则 3：写路径不做 S->X 升级，写操作直接用 X crabbing。
- 规则 4：释放顺序与获取相反（或 RAII 栈式 pop）。

```cpp
// write_set_ 作为 latch 栈
write_set_.push_back(guard_root);
// ...
if (child_safe) {
  write_set_.pop_front(); // 释放最早，或 release 指定层
}
```

---

**Context 与 write_set_**
- bustub Context 在 Insert/Delete 时：

```cpp
struct Context {
  std::deque<WritePageGuard> write_set_;
  page_id_t root_page_id_;
  // header_page 等
};
```

- 作用：
- 按顺序持有路径上 X latch
- split 时访问父 = write_set_.back() 或倒数第二层
- 操作结束清空 write_set_，自动 unlatch

- 如果没有 write_set_：
- 手动 Release 漏一层 -> 其他线程闯入 -> corrupt

---

**共享锁与 Iterator 并发**
- Iterator 持 S latch 当前叶，++ 时：
- 释放旧叶 S latch
- S latch 下一叶

- 若写线程同时 merge 删下一叶：
- 需 crabbing 或版本检查；教学实现常 **测试时读写互斥** 或 **Iterator 不保证与写并发**。

- 工业级：B-link tree、epoch-based reclamation。

---

**Hash Index 的 Latch（对比 P7）**
- extendible hash split：
- X latch directory page
- X latch 旧桶，可能 X latch 新桶
- 目录翻倍时 directory 全局 X latch——热点

- 比 B+Tree 更简单（无树路径），但 directory 是全局瓶颈。

**Optimistic vs Pessimistic（选读）**
- **Pessimistic**：只要 child 可能 split，祖先 X latch 全程不放手——bustub 入门首选。
- **Optimistic**：大多数节点 safe，提前释放祖先；split 时若父已释放，重新 latch 并验证版本——吞吐更高，实现更难。
- 验收时先证明 pessimistic 正确，再考虑优化；Gradescope 不会因为你 crabbing 不够激进而扣分，但会因 race 挂掉。

**Delete 路径 latch 补充**
- Delete underflow 时除路径 latch 外，常需 **X latch 兄弟叶**。
- 加锁顺序：`min(page_id_left, page_id_right)` 先，避免 AB-BA 死锁。
- merge 完成后释放兄弟 guard，再沿 write_set_ 向上处理父 underflow。
