**先把 `P3` 的主线再压缩一遍**
- `P3-1` 讲的是：为什么要有 page/tuple 抽象，为什么不能按记录直接读写磁盘。
- `P3-2` 讲的是：slotted page 布局、slot array、RID、定长/变长、MarkDelete、不变量。
- `P3-3` 讲的是：堆表组织、索引/WAL 接口、bustub 落点、最小实现与调试。

- 所以如果你说自己“学完了 P3”，并不意味着：
- 你能背出 slot array 定义

- 而是意味着：
- 你能从 executor 一路追到 page 字节，并指出每层不变量。

**常见卡点**
- 这些是我带学生时最高频的卡点。你对照看看自己有没有中招。

**卡点 1：RID 理解停留在名词**
- 症状：说 RID 是“记录地址”，但说不清 slot_num 为何不变。
- 破解：亲手跟踪一次 update relocation，观察 slot array 变化。

**卡点 2：只会画空 page，不会画删除后的 hole**
- 症状：以为 Delete 后 free space 一定连续可用。
- 破解：做 P3-2 的插入序列纸上练习。

**卡点 3：TablePage 与 TableHeap 职责混乱**
- 症状：在 TablePage 里找“下一张 page 插入谁”。
- 破解：记住 TableHeap 管多页，TablePage 只管一页。

**卡点 4：忽略 schema 与 bytes 的关系**
- 症状：GetTuple 解析用错 offset。
- 破解：先写 Tuple 序列化/反序列化单元测试，再接 page。

**卡点 5：过早做 compaction + 变长 + 并发**
- 症状：三周还在调 page，主路径 none。
- 破解：严守 P3-3 的阶段 0–2，先定长单页。

**卡点 6：测试只有“插入两条能读”**
- 症状：一删就崩、一满就 silent corrupt。
- 破解：按 P3-3 推荐测试清单补全。

**进入 `P4` 前必须回答的问题**
- 如果你要进入缓冲池，请先口头或书面回答下面 8 个问题。
- 答不上来，建议回到对应小节。

- 为什么数据库读写磁盘以 page 为单位？

**最后收束**
- `P3` 的本质只有一句话：
- `把逻辑上的一行元组，变成磁盘上可批量 I/O、可稳定定位、可与索引和日志协作的 page 内对象。`

- 你前面学的 SQL 和关系代数，最终都要落到某个 RID 指向的 bytes 上。
- 这一课学稳了，你才真正从“会写查询”进入“会写存储引擎”。
