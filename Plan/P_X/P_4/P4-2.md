**Frame 状态机**
- 每个 frame 在任意时刻，可以用几个维度描述：

```text
frame_id
occupied?        (是否装着某个 page)
page_id          (若 occupied，是哪个逻辑页)
pin_count        (多少使用者正在持有)
is_dirty         (内存内容是否比磁盘新)
replacer_state   (是否在 replacer 候选集中)
```

- 典型状态转换：

```text
[Free]
  --加载 page--> [Occupied, pinned, clean]
  --修改 page--> [Occupied, pinned, dirty]
  --Unpin-->     [Occupied, unpinned, dirty/clean]
  --Evict-->     [Free]  (仅当 pin_count==0)
```

**不变量回顾**
- pin_count > 0：不可 evict。
- dirty 且将要 evict：必须先 flush。

**初学者易错点**
- evict 后忘记清 page_id、忘记从 page table 删映射。
- pin_count 减到 0 却未通知 replacer，导致 frame 永远不被驱逐或错误驱逐。

---

**Page Table：page_id -> frame_id**
- page table 回答：`page_id=7 现在在不在内存？若在，在哪个 frame？`

- 常见实现：
- 哈希表：`unordered_map<page_id_t, frame_id_t>`
- 或数组（page_id 范围有限且稠密时）

**操作与 frame 生命周期绑定**
- Fetch 命中：查表得 frame_id，pin++。
- Fetch 未命中：evict 或找 free frame，读盘，插入映射。
- Evict：删映射，frame 变 free 或装新 page。

**如果没有 page table**
- 每次 Fetch 只能线性扫所有 frame 找 page_id，O(n)。
- 并发下更容易不一致。

**FetchPage 伪代码（教学版）**
- 下面逻辑省略 latch，但顺序不能乱：

```cpp
Page *BufferPoolManager::FetchPage(page_id_t page_id) {
  // 1. 查 page table
  if (auto it = page_table_.find(page_id); it != page_table_.end()) {
    frame_id_t frame = it->second;
    frames_[frame].pin_count++;
    replacer_.RecordAccess(frame);  // 视策略而定
    replacer_.SetEvictable(frame, false);  // pin>0 不可驱逐
    return &pages_[frame];
  }

  // 2. 未命中：找 frame
  frame_id_t frame = FindFreeOrEvictableFrame();
  if (frame == INVALID) return nullptr;  // 全是 pinned

  // 3. 若 occupied，先处理旧页
  if (frames_[frame].occupied) {
    if (frames_[frame].is_dirty) FlushPage(old_page_id);
    page_table_.erase(old_page_id);
  }

  // 4. 读盘
  disk_manager_->ReadPage(page_id, pages_[frame].GetData());
  frames_[frame] = {page_id, pin_count=1, dirty=false, occupied=true};
  page_table_[page_id] = frame;
  replacer_.SetEvictable(frame, false);
  return &pages_[frame];
}
```

- 你要能口头讲每一步，而不是背代码。

**UnpinPage 与 replacer 的接口**
- UnpinPage(page_id, is_dirty) 典型语义：
- 找到 frame，pin_count--。
- 若 is_dirty，标记 frame dirty。
- 若 pin_count==0，通知 replacer：此 frame 现在可驱逐。

```cpp
void UnpinPage(page_id_t page_id, bool is_dirty) {
  frame_id_t frame = page_table_[page_id];
  frames_[frame].pin_count--;
  if (is_dirty) frames_[frame].is_dirty = true;
  if (frames_[frame].pin_count == 0) {
    replacer_.SetEvictable(frame, true);
    replacer_.RecordAccess(frame);  // 策略相关
  }
}
```

**为什么 replacer 只管理可驱逐帧**
- pinned frame 根本不允许 evict，放进 LRU 队列没有意义还会误导。
- 这是 bustub 里 `SetEvictable` 存在的原因。

---

**NewPage 与 DeletePage（简述）**
- NewPage：分配新的 page_id，找 frame，初始化 page 内容，建立映射，pin 住。
- DeletePage：通常 pin 住、刷盘或标记、从文件层释放 page_id、evict 出内存。

- 和 TableHeap 扩展、B+Tree 分裂直接相关。
- 第一版 BPM 可先实现 NewPage + Fetch + Unpin + Flush。

---

**FlushPage：谁调用、何时调用**
- 显式 FlushPage(page_id)：
- 把内存 frame 写回磁盘，clear dirty（在成功写盘后）。

- 隐式 flush：
- evict dirty frame 前必须 flush。

**不 flush 就 evict 会怎样**
- 内存里的修改永久丢失。
- 重启后读到旧磁盘版本，违反持久性。

**flush 与 WAL 的边界（预告）**
- 正确系统里，dirty page 刷盘通常要在相应日志已持久化之后。
- 细节在恢复课；你现在要知道：BPM 的 Flush 不是孤立写文件。

---

**替换策略 1：LRU**
- Least Recently Used：驱逐最久未访问的 unpinned frame。

**优点**
- 实现直觉简单（链表 + 哈希）。
- 对有明显时间局部性的负载效果好。

**缺点**
- 全表顺序扫描可能把整表 page 都扫进 pool，挤掉热点页（cache pollution）。
- 每次 access 更新 LRU 有锁和链表开销。

**适用直觉**
- 负载局部性明显、scan 不多。

---

**替换策略 2：Clock（二次机会）**
- 把 frame 组织成环形，指针扫过，给第二次机会。

- 每个 frame 有 reference bit（最近是否被访问）。
- 需要 evict 时，顺时针找：
  - ref=1：置 0，跳过（第二次机会）
  - ref=0：选中 evict

**优点**
- 比严格 LRU 开销低。
- 对 scan 有一定抵抗力（bit 会掉）。

**缺点**
- 近似 LRU，效果取决于负载。
- 实现要小心 ref bit 何时置位（Fetch 命中时）。

---

**替换策略 3：LRU-K**
- 不只看“最后一次”访问，而看“最近 K 次访问历史”的距离。

- 直觉：区分“偶尔被扫过一次的大冷页”和“反复访问的热页”。

**优点**
- 对混合 OLTP + 中等 scan 更稳。
- bustub 常用 LRUKReplacer 作为练习。

**缺点**
- 实现和元数据比 Clock 复杂。
- K 的选择影响效果。

**和 scan 的关系**
- 纯 LRU：大 scan 容易污染 cache。
- LRU-K：若某页只在大 scan 中出现一次，历史距离大，更易被 evict。

---

**性能 bug vs 正确性 bug**
- 你必须学会区分：

```text
性能 bug：替换策略差，命中率低，慢，但结果对
正确性 bug：pin/evict/flush 错序，数据丢、指针悬空、映射不一致
```

- 先把正确性协议写对，再优化 replacer。
- 反过来：LRU 写再漂亮，忘记 flush dirty 也是灾难。

---

**缺页、命中、驱逐：一张状态迁移总表**
- 命中 Fetch：page_table 有 -> pin++ -> 可能更新 replacer。
- 未命中 Fetch：找 frame -> 可能 evict -> ReadPage -> 插入映射 -> pin=1。
- Unpin：pin-- -> 若 0 则 evictable。
- Evict：仅 pin=0 -> dirty 则 flush -> 删映射 -> frame 可用。
- Flush：写盘 -> clear dirty（成功路径）。

- 建议你自己画成状态图，贴在桌边。

**单线程最小 BPM 实现顺序**
- 1. 固定数量 frame 数组 + Page 对象数组。
- 2. page_table_ 哈希。
- 3. FetchPage / UnpinPage / FlushPage。
- 4. 简单 FIFO 或 Clock replacer。
- 5. 单线程测试：满 pool 循环 Fetch 不同 page_id。
- 6. 再加 latch 和多线程（若课程要求）。

**典型测试场景**
- 测试 A：pool size=1，Fetch p1，Unpin，Fetch p2 -> p1 被 evict。
- 测试 B：Fetch p1，不 Unpin，Fetch p2 -> 应失败或 block（看 API）。
- 测试 C：改 p1 为 dirty，evict 前检查磁盘文件已更新。
- 测试 D：同一 page 连续 Fetch 两次，pin_count 正确，Unpin 两次后才 evictable。

**初学者易错点**
- FindFreeOrEvictableFrame 返回了 pin>0 的 frame。
- Evict 后新 page 用了旧 dirty 标记，没 clear。
- page_table 双份映射：两个 frame 指向同一 page_id。
- FlushPage 只写部分 page 大小。
- 把 replacer 的 “RecordAccess” 在 pin>0 和 pin=0 时语义搞混。
