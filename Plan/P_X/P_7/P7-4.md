```text

-> key hash 到 directory（目录）索引

-> 桶满则 split（分裂），必要时目录翻倍
-> 维护 global/local depth（全局/局部深度）不变量
-> bustub ExtendibleHashTable 实现这套协议
```

**和后续课程的关系**
- `P8 B+Tree`：有序索引主角，补 hash 做不了的 range/order。
- `P10 Latch`：并发 B+Tree 和 hash index 都要 latch；P7 的单线程正确是 P10 的前提。
- `HashJoin/Aggregation`：执行器里内存哈希，思路相通但生命周期不同。

- 进入 P8 前，你最好心里有这样一张选型表：

```text
查询类型           首选索引
--------------------------------
点查 id=?          Hash 或 B+Tree
范围 a<x<b         B+Tree
排序 ORDER BY      B+Tree
全表扫描           无索引 / Seq Scan
```

**Gradescope / 项目常见失败模式**
- `Timeout`：Insert 递归 split 无退出条件——检查 local_depth 是否严格递增、是否忘记重试 Insert。
- `Memory leak`：split 分配新 bucket page 但未 pin/unpin 配对——检查 PageGuard 析构。
- `Wrong answer on Remove`：bitmap 未 ClearOccupied——单独写 Remove 后再 Insert 同一 bucket 的测试。
- `Parallel test fail`（若已做 P10）：先确认单线程 StressTest 100% 通过，再查 latch。
