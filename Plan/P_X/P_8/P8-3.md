**边界条件清单**

**1. 空树 Insert**
- 第一笔 Insert 创建 root leaf。
- 测试：Insert (1,r1) 后 GetValue(1) 成功，height=1。

**2. 重复 Insert 同一 key**
- bustub 通常 Update rid，不增加 key 数。
- 测试：Insert (k,v1), (k,v2)，size 不变，Get 得 v2。

**3. 连续 Insert 直到根分裂**
- 树高从 1 变 2。
- 打印 root 的 children 数 == 2。

**4. 连续 Insert 触发仅叶分裂、不增高层**
- 验证父未满时 height 不变。

**5. Delete 到 min_keys 边界**
- 不触发 merge 的删除。

**6. Delete 触发 redistribute**
- 兄弟有多余 key 时借键。

**7. Delete 触发 merge**
- 两叶合并，父 underflow 递归。

**8. Delete 导致 root 降级**
- root 只有一个 child 时，child 变新 root，height--。

**9. 删光所有 key**
- 树变空或空叶，Insert 仍可继续。

**10. Iterator 全覆盖**
- Begin() 到 End() 遍历 key 与 sorted vector 一致。

**11. Range scan 边界**
- 空 range、单点 range、跨多叶 range。

**12. 最大/最小 key 反复删插**
- 测链表头尾。

**陷阱 1：分隔 key 语义与实现不一致**
- bustub 内节点查找常用：
- `keys[i]` 是第一个大于 search_key 的分界，走 `children[i]`（具体看 header 注释）。
- 你必须读项目文档，不能凭其他教材硬套。

- 会怎样：
- 同一套 Insert 数据，一种规则下正确，换规则全错。

- 调试：
- 固定 5 个 key 的小树，对每个 key 打印 Lookup 走的 child index。

---

**陷阱 2：叶 split 后父 key 选错**
- 常见规则：父插入**新叶的最小 key**。
- 若误插中间 key：
- 右子树范围划分错误，部分 key 查不到。

- 验证：
- split 后，左叶 max < 父分隔 key <= 右叶 min（按实现调整不等号）。

---

**陷阱 3：next_page_id 在 merge 时未跳过被删叶**
- merge L 和 R：

```text
L.keys += R.keys
L.next = R.next   // 跳过 R
释放 R 的 page
```

- 若 L.next 仍指向 R：
- Iterator 读到已释放页或重复 key。

---

**陷阱 4：Internal split 丢 child**
- children 比 keys 多 1。
- split 时必须把 child 精确分到左右内节点。

- 症状：
- 某些 key 区间完全 unreachable。

- 调试：
- split 后 assert 左右 child 覆盖的 key 范围连续且无重叠。

---

**陷阱 5：Delete 不更新父分隔 key**
- 删除叶最小 key 后，父仍保留旧边界。

- 症状：
- Lookup 走 left child，miss 实际在 right 的数据。

- 修复：
- Delete 后沿 Context 向上，若删的是子树最小 key，更新父。

---

**陷阱 6：max_size 与 min_size 算错**
- bustub 常用 compile-time 常量算 page 能存几个 key。

```cpp
// 示意：根据 PAGE_SIZE 和 sizeof(key/page_id) 算
int max_keys = InternalPageMaxSize();
int min_keys = max_keys / 2;  // 或实现定义
```

- 若 max 算大：
- 实际写入越界，corrupt buffer pool。

**Test 6: DeleteReverse**

- 随机 Insert/Delete/Get，与 map 对拍。

**Test 8: RootShrink**
- 构造 height=2，删到 root 只剩一个 child，assert height=1。

**Test 9: LeafLinkIntegrity**
- 维护 ref 的 leaf 顺序，每次操作后 walk next 与 key 排序一致。

```cpp
void CheckLeafChain(BPlusTree &tree) {
  auto it = tree.Begin();
  int prev = INT_MIN;
  while (!it.IsEnd()) {
    assert(it.Key() > prev);
    prev = it.Key();
    ++it;
  }
}
```

**并发预告（P10）**
- 单线程 PrintTree 正确是前提。
- 并发 Insert 相邻 key 可能同时 latch 同一路径父节点。
- Delete 与 Insert 并发可能 merge 与 split 交错——P10 用 latch crabbing 解决。
- P8-3 不要过早开多线程，否则无法定位是结构 bug 还是 race。

---

**PageGuard 生命周期（单线程也建议用）**
- bustub 推荐 FetchPageRead/Write 返回 Guard，析构自动 Unpin。

```cpp
{
  WritePageGuard guard = bpm->FetchPageWrite(page_id);
  auto *leaf = guard.AsMut<BPlusTreeLeafPage>(...);
  leaf->Insert(key, rid);
} // unpin
```

- 若手动 Fetch 不 Release：
- buffer pool 被 pin 满，测试 hang。

**常见卡点**
- `Insert 全过，Delete 挂`
  - 只测了 Insert；补 Test 5–7。

- `Get 过，Iterator 乱序`
  - next 指针或 split 后半顺序错。

- `本地小数据过，大数据 random fail`
  - max_size 越界或 internal split child 错。

- `Print 看起来对，Get 偶尔 miss`
  - 父分隔 key stale，Delete 路径问题。
